# Plan 01-03: Frontend State + Event Reducer

## Objective
Add `ratelimit` to the SolidJS frontend state and handle the `ratelimit.updated` SSE event in the event reducer so the web UI can reactively display rate limit data.

## Context

- `packages/app/src/context/global-sync/event-reducer.test.ts` — Test patterns (first 50 lines)

**How SSE events flow to the reducer:**
1. Backend `Bus.publish(Event.Updated, payload)` → `GlobalBus.emit("event", {...})` (bus/index.ts:59)
2. SSE `/event` endpoint streams it (server/routes/global.ts:81-83)
3. Frontend receives event in global-sync, dispatches to `applyDirectoryEvent`
4. Switch on `event.type` → update store via `setStore`

**The `ratelimit.updated` event payload shape** (from Plan 01-01):
```ts
{
  providerID: string,
  requests?: { limit: number, remaining: number, reset?: string },
  tokens?: { limit: number, remaining: number, reset?: string },
  input?: number,
  output?: number,
  time: number,
}
```

## Codebase Conventions (MANDATORY)
- SolidJS: prefer `createStore` over multiple `createSignal`
- Use `reconcile` for deep object updates in store
- No destructuring. Use dot notation.
- No `else`. Early returns only.
- No semicolons, 2-space indent.

test("ratelimit.updated stores rate limit info by providerID", () => {

      properties: {
        providerID: "anthropic",
        requests: { limit: 60, remaining: 55, reset: "2025-03-16T12:00:00Z" },
        tokens: { limit: 100000, remaining: 90000, reset: "2025-03-16T12:01:00Z" },
        time: 1710590400000,
      },
    },
    store,
    setStore,
    push: () => {},
    directory: "/test",
    loadLsp: () => {},
  })
  expect(store.ratelimit["anthropic"]).toBeDefined()
  expect(store.ratelimit["anthropic"].requests?.limit).toBe(60)
  expect(store.ratelimit["anthropic"].requests?.remaining).toBe(55)
  expect(store.ratelimit["anthropic"].tokens?.limit).toBe(100000)
