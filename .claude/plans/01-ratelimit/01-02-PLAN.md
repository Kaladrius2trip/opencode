# Plan 01-02: Processor Integration — Extract Headers at finish-step

## Objective
Wire the `RateLimit` module into `processor.ts` so that on every `finish-step` event, Anthropic rate limit headers are extracted from `value.response.headers` and published via the bus.

## Context

**Read these files:**
- `packages/opencode/src/session/processor.ts` — Lines 245-289 (finish-step handler)
- `packages/opencode/src/provider/ratelimit.ts` — The module created in Plan 01-01
- `packages/opencode/src/session/llm.ts` — Lines 30-44 (StreamInput type, has `model: Provider.Model`)

**AI SDK type for finish-step (from `ai@5.0.124`):**
```ts
{
  type: 'finish-step';
  response: LanguageModelResponseMetadata;  // { id, timestamp, modelId, headers?: Record<string, string> }
  usage: LanguageModelUsage;
  finishReason: FinishReason;
  providerMetadata: ProviderMetadata | undefined;
}
```

So `value.response.headers` is `Record<string, string> | undefined`.

**Data flow:** `input.model.providerID` (string like "anthropic") is already available in the processor's closure via `input.model`.

### Task 1: Edit processor.ts — Add header extraction
**Type:** code
**Files:** `packages/opencode/src/session/processor.ts` — EDIT

**What to change:**

1. Add import at top of file:
   ```ts
   import { RateLimit } from "@/provider/ratelimit"
   ```

2. In the `case "finish-step":` block (line 245), AFTER the existing usage tracking code (after line 253 `input.assistantMessage.tokens = usage.tokens`), add:
   ```ts
   if (value.response.headers) {
     RateLimit.update(input.model.providerID, value.response.headers)
   }
   ```

   This goes BEFORE the `await Session.updatePart(...)` call on line 254 — it's a fire-and-forget side effect that shouldn't block the main flow.

**Why this location:** The `finish-step` event fires after every LLM response step. `value.response.headers` contains the raw HTTP response headers from the provider. For Anthropic, these include `anthropic-ratelimit-*` headers. For non-Anthropic providers, `RateLimit.update()` will call `parse()` which returns `undefined` and does nothing — graceful degradation.

### Task 2: Add integration-style test
**Type:** test
**Files:** `packages/opencode/test/provider/ratelimit.test.ts` — EDIT (append)

Add a test that verifies the `update` function stores state and can be retrieved:

```ts
import { tmpdir } from "../fixture/fixture"
import { Instance } from "../../src/project/instance"

test("update stores and retrieves rate limit data", async () => {
  await using tmp = await tmpdir()
  await Instance.provide({
    directory: tmp.path,
    fn: async () => {
      const headers = {
        "anthropic-ratelimit-requests-limit": "60",
        "anthropic-ratelimit-requests-remaining": "55",
        "anthropic-ratelimit-requests-reset": "2025-03-16T12:00:00Z",
        "anthropic-ratelimit-tokens-limit": "100000",
        "anthropic-ratelimit-tokens-remaining": "90000",
        "anthropic-ratelimit-tokens-reset": "2025-03-16T12:01:00Z",
      }
      RateLimit.update("anthropic", headers)
      const result = RateLimit.get("anthropic")
      expect(result).toBeDefined()
      expect(result!.requests!.limit).toBe(60)
      expect(result!.requests!.remaining).toBe(55)
      expect(result!.tokens!.limit).toBe(100000)
    },
  })
})

test("update with non-anthropic headers is a no-op", async () => {
  await using tmp = await tmpdir()
  await Instance.provide({
    directory: tmp.path,
    fn: async () => {
      RateLimit.update("openai", { "x-ratelimit-limit": "100" })
      const result = RateLimit.get("openai")
      expect(result).toBeUndefined()
    },
  })
})
```
